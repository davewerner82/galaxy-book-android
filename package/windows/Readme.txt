Galaxy Book 12 LTE SM-W727 | Native Android hardware test
This package uses your verified July 2024 BlissOS Zenith 16.9.6 installation as its system image. The kernel and all Linux modules are from the same experimental build. Stock Android and Windows keep their own data. This is a hardware-test build. Stage it first.

1. Extract the entire ZIP to one folder on C:. Run Check.cmd, then Stage.cmd as administrator. Windows may show its normal security and elevation prompts. Stage copies the stock system to C:\GalaxyBookTest and creates a fresh 2 GiB Android data file. Leave your existing C:\AndroidOS alone.
2. Only proceed to Arm.cmd after you have confirmed Windows recovery access and saved your work. Remove the SD card for the test. Arm checks Windows is the default, C: is fully decrypted, and Secure Boot is already off. If any check fails, stop and keep the printed message. Do not disable encryption for this test. Arming backs up the existing Android GRUB configuration to C:\GalaxyBookTest\original-grub.cfg and requests a single firmware boot. It does not restart the tablet.
3. Use Windows Restart, not Shut down. Test whether Android reaches the welcome screen and whether both finger touch and the pen work. If stuck, hold the power button until off, then turn on. Windows is the normal firmware default after the one-time choice is consumed.
4. Back in Windows, run Restore.cmd as administrator. It verifies and restores the original GRUB menu. Use it before restart to cancel an armed test. Logs in C:\GalaxyBookTest\logs include early kernel messages, loaded modules and registered input devices. They cover early boot through Android init handoff. Android UI startup and late crashes require additional device evidence.
5. Retain the extracted package, stage folder and original GRUB backup until recovery has been verified. The boot test changes neither partition sizes nor the Windows boot loader. A confirmed recovery path and working hardware are necessary before considering permanent installation.
